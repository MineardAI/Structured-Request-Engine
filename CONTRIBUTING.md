# Contributing

Contributions should preserve the repository's contract-first boundaries and the distinction between implementation evidence, formal contract standing, and production authority.

Before submitting a change, run the verification commands in `README.md`. Changes to a contract boundary should include focused behavioral tests and update the applicable implementation mapping, traceability, and evidence records. Do not introduce ambient profile or registry lookups, semantic invention, authorization, execution, or durable persistence without an explicitly governing contract and reviewable authority.

Keep changes focused, deterministic, documented, and free of credentials or private machine paths. Historical evidence should be preserved; current-status records may be updated when the repository state changes.
